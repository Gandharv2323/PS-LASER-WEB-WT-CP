1. Project Overview

1.1 Purpose

PS Laser is a sheet-metal and CNC laser-cutting job shop at Gat No. 753, Velu, Tal. Bhor, Dist. Pune 412205. This document specifies the requirements and architecture of the web platform built for the shop: a public website, an instant indicative cost estimator, enquiry and drawing capture, order tracking, and staff back-office tools. The platform is also the course project for CS3111 Web Technologies, so each syllabus unit is implemented as a real feature of the same business.

1.2 Scope

In scope: the seven software services listed in Section 7, the shared MySQL database, the optional MongoDB activity log, and the local run environment on a Windows PC.

Out of scope: integration with shop-floor machines (the lasers, press brake, turret punches, welder and coating plant are described for context only), payment processing, e-mail/SMS delivery, public internet deployment, and the syllabus lab practicals (electricity bill, book store and similar), which are intentionally not part of this project.

1.3 Objectives

  • Present the shop's real machines, services and contact channels on a responsive website.
  • Give customers an instant, clearly labelled indicative price from a rate card the owner controls.
  • Capture enquiries and drawings reliably and let staff manage them.
  • Let customers track a job to dispatch with an order number and phone number.
  • Keep seven independently built services consistent through one schema and one contract.

1.5 Business facts the system is built on

Seven facilities are described, from the company profile: HSG 3 kW fiber laser, Genesis 1.5 kW fiber laser (both 3 m × 1.5 m beds), 175 t CNC press brake (3 m), Amada 32 t and 16 t CNC turret punches, HSG 1.5 kW handheld laser welder and a PLC powder-coating plant. Laser-cutting capacity is mild steel 16 mm, stainless steel 12 mm, aluminium 8 mm, brass 4 mm and copper 4 mm. The estimator's price rates are sample values (database flag rates.is_sample = 1); machines, services and contact data are real.

7. System Architecture

The system has five tiers: client, presentation, application/API, data, and (for context) the physical shop. Table 9 states the responsibility of each component; Section 8 shows the diagram.

File storagePrivate drawing uploads and request/event logs on disk—

Key design decisions. (1) Contract-first: services/CONTRACT.md fixes the schema, JWT claims, price formula and API shapes. (2) Shared schema: PHP, Laravel and the servlet application use MySQL directly, which keeps each syllabus unit self-contained at the cost of repeating business rules. (3) Graceful degradation: the public Next.js estimator and the React portal keep working with labelled fallbacks when Spring is unreachable. (4) One rounding rule: each cost line is rounded half-up to two decimals, then added.

9. Data Flow and Workflow

9.1 Main operational workflow

  1. A customer opens the website, chooses a material and enters the part details; the estimator returns an indicative price breakdown.
  2. The customer taps Get Quote, which opens WhatsApp with a pre-filled message, or submits the enquiry form with an optional drawing.
  3. Node stores the enquiry and drawing and returns a WhatsApp link; staff see the enquiry in the Laravel, Node or Spring admin views.
  4. After the shop agrees the real price outside the system, staff create a work order and move it through received → cutting → bending → welding → coating → inspection → dispatched.
  5. Each status change adds an event row; the customer sees the timeline on /track (or the JSP page) by entering order number and phone; staff see live updates on the dashboard.

9.2 Key data flows

Table 10. Data flows
FlowPath
EstimateBrowser → Next.js /api/estimate → Spring POST /api/quotes/estimate → reads materials, rates, settings in MySQL → breakdown JSON → page. If Spring is down the TypeScript formula answers and the page says "Offline estimate (sample)".
TrackingBrowser → /track?orderNo=&phone= (server-rendered) → Spring GET /api/work-orders/track → work_orders + work_order_events → timeline.
Status changeStaff action (Laravel, JSP or Spring admin) → update work_orders and insert work_order_events → Spring publishes /topic/work-orders → dashboard.
EnquiryNext.js server action or React portal → Node POST /api/enquiries (JSON or multipart) → enquiries and uploads rows, private file on disk → {id, whatsappUrl}.
LoginSpring POST /api/auth/login → JWT (8 h); Node accepts the same token; Laravel and JSP keep their own sessions against the same users table.

9.3 Estimate formula (identical in PHP, Spring, JSP and Next.js)

areaM2   = lengthMm x widthMm / 1e6
weightKg = areaM2 x thicknessMm x density_g_cm3
material = weightKg x material_rate_per_kg
cutting  = (cutLengthMm / 1000) x cut_rate_per_m
piercing = pierces x pierce_rate
bending  = bends x settings.bend_rate_inr
coating  = powderCoat ? areaM2 x 2 x settings.powder_coat_rate_per_sqm : 0
perPart  = sum of the five lines, each rounded half-up to 2 dp
subtotal = round2(perPart x quantity)
gst      = round2(subtotal x settings.gst_percent / 100)
total    = subtotal + gst

Worked check [V]. Mild steel 2 mm, 500 × 300 mm, cut 1600 mm, 4 pierces, 2 bends, powder-coated, quantity 10, with the sample rates (75.00 INR/kg, 10.00 INR/m, 1.00 per pierce, 8 per bend, 120 per m², 18 % GST) gives per part 248.63, subtotal 2,486.30, GST 447.53 and total INR 2,933.83. This was returned by the Spring API on 16 Oct 2026 and by Spring, Next.js, PHP and the Java servlet application on 14 Oct 2026.

Errors use one shape: {status, error, message, fieldErrors?}. The token is sent as Authorization: Bearer <token>.

10.2 Node/Express API (base http://localhost:4000)

  • GET /api/health returns {ok, db}; GET /api/catalogue returns machines and services (cached).
  • POST /api/enquiries accepts JSON or multipart with an optional drawing file and returns 201 {id, whatsappUrl}.
  • GET /api/enquiries and PATCH /api/enquiries/:id require a JWT with role admin or staff.
  • GET / serves the API documentation page.

10.3 Other interfaces

  • Next.js route handlers: POST /api/estimate, POST /api/auth/login, POST /api/auth/logout, GET /api/work-orders.
  • WebSocket/STOMP: topic /topic/work-orders published by Spring.
  • WhatsApp: https://wa.me/917719976990?text=… (external; no server needed).
  • CORS: allowed origins are http://localhost:3001, :5173, :8000, :8001 and :8080.

10.4 External dependencies

  • WhatsApp (wa.me links) — external service; if unavailable the quote can still be requested by telephone.
  • CDN assets for Bootstrap and jQuery (PHP estimator) and web fonts — need internet access.
  • Package registries (npm, Maven Central, Packagist) — needed only for first-time installs.
  • No hardware, payment, e-mail or SMS dependency exists.

11. Installation and Deployment Requirements

11.1 Preparation

  • Free at least 5 GB on the drive that holds the project [P] (the handbook advises keeping 2 GB free before installing).
  • Install Node.js 24, JDK 21 and XAMPP (PHP 8.2, MariaDB, Tomcat 8.5); set JAVA_HOME to the JDK folder.

11.3 Production deployment (proposed, not done) [P]

  • Replace the development database credentials and the development JWT_SECRET with secrets from a secrets manager.
  • Serve every service behind HTTPS on a real domain; set the site's metadataBase, sitemap and robots rules.
  • Use a managed MySQL with automated backups; use a persistent MongoDB (not the embedded instance).
  • Containerise the services (docker-compose) and add a CI pipeline that runs the automated tests.

12. Assumptions, Constraints and Future Enhancements

12.1 Assumptions

  • The shop owner will supply real rates before any customer relies on an estimate.
  • Final prices are agreed on WhatsApp or by telephone; the website only gives an indication.
  • Staff update job status manually and have access to a browser.
  • Customers know the order number and the phone number used when the order was created.

12.2 Constraints and known limitations

  • Rate card is sample data; product and gallery pictures are representative renders, not photographs of finished PS Laser jobs; demo orders PSL-DEMO-001/002 are fake test data.
  • Runs locally only; no domain, HTTPS or public deployment. Development secrets must not be used publicly.
  • No machine integration, payment, e-mail or SMS; enquiry delivery is a database row plus a WhatsApp link.
  • Embedded MongoDB loses its data on restart; Docker was not available during testing.
  • Not tested: visual responsive pass, every image, React portal → Node → database enquiry path, live push to the dashboard, upload re-test with real files, load and performance.
  • Some engineering text on the site (for example which laser suits thick plate) is inferred and awaits owner confirmation.

12.3 Future enhancements

  1. Enter the real rate card and add a "valid until" date to quotes.
  2. Send e-mail or WhatsApp Business notifications when a job status changes.
  3. Parse DXF drawings to propose cut length and pierce counts automatically.
  4. Add end-to-end browser tests (Playwright) and a one-command start script or docker-compose file.
  5. Deploy to a managed host with HTTPS, backups and monitoring.
  6. Add owner-supplied photographs and, only if genuine, testimonials and a client list.
